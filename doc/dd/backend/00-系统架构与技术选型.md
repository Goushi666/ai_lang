# 后端设计 · 系统架构与技术选型

## 1. 整体架构（与当前仓库一致）

```
┌─────────────────────────────────────────────────────────┐
│                    API 层 (FastAPI)                      │
├─────────────────────────────────────────────────────────┤
│  REST 路由  │  CORS  │  WebSocket  │  JWT 认证（用户级别） │
├─────────────────────────────────────────────────────────┤
│              业务逻辑层 (Service)                         │
├─────────────────────────────────────────────────────────┤
│  传感器/告警  │  环境分析/监测  │  车辆 MQTT  │  视频代理   │
│  Agent（LangGraph + 工具 + 多层记忆 + 工业审计/反思）      │
├─────────────────────────────────────────────────────────┤
│              数据访问层 (Repository)                      │
├─────────────────────────────────────────────────────────┤
│  SQLite（app.db，业务与 Agent 会话等）                    │
│  SQLite FTS5（knowledge_fts.db，知识块检索，可选独立文件）  │
│  MQTT Broker（车端/机械臂下行，按配置启用）                 │
└─────────────────────────────────────────────────────────┘
```

## 2. 技术选型

- **Web 框架**：FastAPI 0.104+
- **主数据库**：**SQLite** + `aiosqlite`（`app.db`：传感器、告警、用户、Agent 会话与多层记忆表等）
- **知识检索**：**SQLite FTS5**（`KnowledgeService`，默认 `data/knowledge_fts.db`）；Markdown 分块见 `app/services/knowledge/chunker.py`
- **Agent 编排**：**LangGraph** + `langchain-core`（单图支撑 JSON 与 SSE，见 [08-Agent-LangGraph编排架构.md](./08-Agent-LangGraph编排架构.md)）
- **消息队列 / 物联网**：MQTT（车控与机械臂；配置见 `app/core/mqtt.py`）
- **ORM**：SQLAlchemy 2.0（异步会话）
- **异步**：asyncio
- **认证**：JWT（python-jose）+ bcrypt；用户级别 `viewer` / `operator` / `admin`
- **数据验证**：Pydantic v2
- **部署**：Uvicorn（开发），生产可配合 Gunicorn 等

## 3. 扩展与历史说明

- 配置中仍保留 **`VECTOR_DB_PATH` / `EMBEDDING_*`** 等与旧版 Chroma 向量方案相关的字段名，**当前默认知识链路不依赖 Chroma**；若未来再接独立向量库，可在 `KnowledgeService` 侧替换实现而不改 Agent 工具契约。
- 若后续将业务库迁移至 **MySQL**、热点缓存至 **Redis**，分层（api → service → repository）保持不变即可。
